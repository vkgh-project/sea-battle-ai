# Морський бій: людина — Google Gemini

Браузерна гра для кількох незалежних користувачів. React + Vite + TypeScript, Fastify + Node.js. Gemini автоматично обирає постріли через серверний API. Копіювати промпти або вставляти відповіді не потрібно. Партії зберігаються лише в пам’яті сервера.

## Google Gemini Free Tier

1. Створіть API-ключ у [Google AI Studio](https://aistudio.google.com/apikey) для проєкту з тарифом Free.
2. Скопіюйте `.env.example` у `.env` і заповніть `GEMINI_API_KEY`.
3. Залиште `AI_MODE=gemini` та `GEMINI_MODEL=gemini-3.5-flash-lite` (стандартні значення).
4. Запустіть гру, розставте флот і стріляйте. Коли хід перейде до AI, сервер автоматично звернеться до Gemini.

За [прайсингом Google](https://ai.google.dev/gemini-api/docs/pricing), Gemini 3.5 Flash-Lite має безкоштовні вхідні та вихідні токени на Free Tier. Тариф визначається проєктом Google, а не параметром у коді: використовуйте проєкт Free без підключеного платного billing. Код не вмикає billing і не перемикає модель автоматично. Для іншої доступної моделі змініть `GEMINI_MODEL`.

[Ліміти Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) залежать від моделі та проєкту; актуальні значення доступні у Google AI Studio. Квота спільна для всіх гравців цього проєкту. Один постріл AI — один API-запит, після влучання потрібен наступний запит. При HTTP 429 гра зберігає стан і пропонує повторити хід. Автоматичних повторів немає; при вичерпанні денної квоти потрібно дочекатися її поновлення. Денна квота поновлюється опівночі за тихоокеанським часом. `MAX_AI_CONCURRENCY=1` обмежує одночасні ходи, але не замінює ліміти Google.

Ключ доступний лише серверу. Не додавайте його до `VITE_*`, клієнтського коду або Git. На Free Tier Google може використовувати передані дані для покращення своїх продуктів; гра надсилає лише правила та відкриті AI результати пострілів.

## Запуск локально

Потрібен Node.js 22 або новіший (рекомендовано 24).

```sh
npm ci
cp .env.example .env
# Заповніть GEMINI_API_KEY у .env
npm run dev
```

На Windows використовуйте `Copy-Item .env.example .env`; за потреби — `npm.cmd` замість `npm`.
Відкрийте адресу, яку виведе Vite (зазвичай http://localhost:5173).
Для перевірки без ключа задайте `AI_MODE=demo`: ходи обиратиме локальний алгоритм, а інтерфейс явно покаже демо-режим. Помилка Gemini ніколи не перемикає гру на демо.

```sh
npm test
npm run build
npm start
```

Зібрана гра доступна на http://localhost:3000.

## Render

1. Завантажте код у свій GitHub-репозиторій разом із `package-lock.json`, без `.env` і `node_modules`.
2. Створіть Render Web Service або Blueprint із `render.yaml`.
3. Build command: `npm ci --include=dev && npm run build`. Start command: `npm start`. Health check: `/api/health`.
4. У Environment задайте `GEMINI_API_KEY`, `GEMINI_MODEL=gemini-3.5-flash-lite`, `AI_MODE=gemini`, `MAX_AI_CONCURRENCY=1`, `NODE_ENV=production`.
5. Задайте `APP_ORIGIN` як точну адресу сервісу або власного домену без кінцевого `/`, наприклад `https://sea-battle-ai.onrender.com`.
6. Залиште один екземпляр сервера; диск не потрібен. Blueprint зберігає план Render `0.5c-512mb`; оплата хостингу окрема від Gemini Free Tier. На Render Free засинання сервера призводить до втрати партій.

Для наявного сервісу оновіть змінні оточення за пунктом 4, видаліть старі змінні попереднього AI-провайдера та виконайте Save and deploy.
Збірка потребує `devDependencies` (TypeScript, Vite та типів), навіть коли `NODE_ENV=production`. `.npmrc` також вмикає їх встановлення.

## Правила та інтерфейс

Поле 10×10. Флот 4,3,3,2,2,2,1,1,1,1. Кораблі не торкаються навіть кутами. Людина ходить першою; влучання та потоплення дають повторний хід. Вода навколо потоплених кораблів автоматично позначається. При завершенні гри показується флот суперника.

Перед початком можна випадково розставити флот або очистити поле й розмістити кораблі вручну в заданому порядку. Кнопка напрямку змінює орієнтацію. Клік по вже розміщеному кораблю очищає весь флот.

## Ізоляція та пам’ять

- Криптографічно випадковий токен у HttpOnly/SameSite=Strict cookie; у production також Secure і префікс `__Host-`.
- Кожна сесія має одну партію. Чужий `gameId` не дає доступу до неї; різні браузери та профілі мають незалежні сесії.
- Блокування та версія стану захищають від повторних і застарілих пострілів. Вкладки одного браузера мають спільну сесію.
- Запит Gemini містить правила, попередні постріли AI, потоплені кораблі, залишок флоту та дозволені координати. Прихований флот людини, cookie, ідентифікатори сесій і дані інших партій не передаються.
- Gemini обирає `target` зі списку дозволених клітинок (`enum`, формат `рядок,колонка`). Сервер перетворює вибір на координати. Сервер перевіряє дозволену клітинку та сам визначає результат пострілу.
- Таймаут запиту — 25 секунд. Помилка не змінює поле; кнопка «Повторити хід AI» відновлює поточний хід без повтору пострілу людини.
- До 1000 сесій; неактивні сесії видаляються через 60 хвилин. Перезапуск, оновлення або засинання процесу знищують усі партії.
- Клієнт отримує свій флот і лише відкриту інформацію про суперника. Опитування відновлює стан після оновлення сторінки або розриву мережі.

Ліміти сервера налаштовуються через `MAX_SESSIONS`, `MAX_AI_CONCURRENCY`, `SESSION_TTL_MINUTES`. Для публічного запуску враховуйте спільну квоту Google та навантаження.

## Перевірки

У журналі сервера подія `ai_turn_failed` містить категорію, HTTP-статус, відомий код помилки та `providerMessage` — пояснення Google до 1000 символів із видаленими API-ключами й токенами. Повна відповідь провайдера не записується. Для `invalid_response` поле `reason` відрізняє порожню відповідь, некоректний JSON та недоступну клітинку. Для `400 INVALID_ARGUMENT` перевірте саме `providerMessage`: він вказує, який параметр або налаштування Google відхилив. `authentication` — проблема ключа; `permission` — права або доступність API; `model` — доступ до моделі; `rate_limit` — частота запитів або квота Free Tier. Гра показує відповідне повідомлення українською.

`npm test` перевіряє правила, приховування флоту, ізоляцію сесій, повторні ходи, автоматичні ходи AI та Gemini API через підставний HTTP-транспорт. Зовнішніх запитів і витрат у тестах немає. `npm run build` перевіряє типи та збирає клієнт і сервер.
