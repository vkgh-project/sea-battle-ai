# Морський бій: людина — ChatGPT

Браузерна гра для кількох незалежних користувачів. React + Vite + TypeScript, Fastify + Node.js, OpenAI Responses API. Бази даних, файлів стану та постійного диска немає.

## Запуск локально

Потрібен Node.js 22 або новіший (рекомендовано 24).

```powershell
npm.cmd install
Copy-Item .env.example .env
# Заповніть OPENAI_API_KEY у .env. Не передавайте ключ у чат і не комітьте його.
npm.cmd run dev
```

Відкрийте адресу, яку виведе Vite (зазвичай http://localhost:5173).
Для перевірки без платних API-запитів у `.env` встановіть `AI_MODE=demo`: інтерфейс явно повідомляє, що це локальний алгоритм. Режим OpenAI ніколи автоматично не замінюється демо.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd start
```

Зібрана гра доступна на http://localhost:3000. На Linux/macOS використовуйте `npm` замість `npm.cmd`.

## Render

1. Завантажте код у свій GitHub-репозиторій разом із `package-lock.json`, без `.env` і `node_modules`.
2. Створіть Render Web Service з цього репозиторію або Blueprint із `render.yaml`.
3. Build command: `npm ci && npm run build`. Start command: `npm start`. Health check: `/api/health`.
4. Додайте секрет `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-4o-mini`, `AI_MODE=openai`, `NODE_ENV=production`.
5. Встановіть `APP_ORIGIN` у точну адресу сервісу, наприклад `https://sea-battle-ai.onrender.com`. Для власного домену використовуйте його адресу. Без кінцевого `/`.
6. Залиште один екземпляр сервера. Диск підключати не потрібно. Blueprint обирає платний план `0.5c-512mb`; тариф можна змінити у Render. На Free засинання сервера призводить до втрати партій.

API-ключ доступний лише серверу. Браузер користувача не потребує акаунта OpenAI.

## Правила та інтерфейс

Поле 10×10. Флот 4,3,3,2,2,2,1,1,1,1. Кораблі не торкаються навіть кутами. Людина ходить першою; влучання та потоплення дають повторний хід. Вода навколо потоплених кораблів автоматично позначається. При завершенні гри показується флот суперника.

Перед початком можна випадково розставити флот або очистити поле й розмістити кораблі вручну в заданому порядку. Кнопка напрямку змінює орієнтацію. Клік по вже розміщеному кораблю очищає весь флот.

## Ізоляція та пам'ять

- Криптографічно випадковий токен у HttpOnly/SameSite=Strict cookie. У production cookie також Secure та має префікс `__Host-`.
- `Map<sessionToken, Session>` містить одну поточну партію для кожної сесії. Сервер шукає партію тільки всередині сесії її власника; чужий `gameId` не дає доступу.
- Блокування ходу діє на конкретну партію. Версія стану відхиляє повторні та застарілі постріли. У різних вкладках одного браузера спільна сесія; різні браузери/профілі мають незалежні сесії.
- Запити до AI не містять cookie, ідентифікаторів сесій, прихованого флоту людини чи даних інших партій. `store: false`; попередні conversation/response ID не використовуються. Це не обіцянка нульового збереження з боку API-провайдера.
- Кожний постріл AI — окремий запит. Передаються правила, його постріли, потоплені кораблі, залишок флоту і дозволені координати. Сервер перевіряє відповідь і сам визначає результат.
- До 8 одночасних API-запитів за замовчуванням. При перевантаженні чи помилці API гравець може повторити хід, а вже зроблені постріли зберігаються. Таймаут одного API-запиту — 25 секунд.
- До 1000 сесій; неактивні сесії видаляються через 60 хвилин. Сервер прибирає їх щохвилини; активний хід не видаляється. Перезапуск, оновлення або засинання процесу знищують усі партії.
- Клієнт отримує повний власний флот і тільки відкриту інформацію про суперника. Опитування стану дозволяє відновитися після оновлення сторінки та тимчасового розриву мережі.

Ліміти налаштовуються через `MAX_SESSIONS`, `MAX_AI_CONCURRENCY`, `SESSION_TTL_MINUTES`. Обмеження HTTP-запитів за IP та частоти створення партій зменшують випадкове навантаження. Для публічного запуску з великим трафіком потрібні додаткові захист від зловживань та контроль витрат у проєкті OpenAI. Максимальну кількість гравців треба визначати навантажувальним тестом.

## Перевірки

`npm test` перевіряє правила, розміщення, приховування флоту, розділення сесій, відмову чужому користувачу, повторні ходи та поведінку при збоях AI. Тести не звертаються до OpenAI.
