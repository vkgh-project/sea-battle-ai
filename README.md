# Морський бій: людина — ChatGPT

Браузерна гра для кількох незалежних користувачів. React + Vite + TypeScript, Fastify + Node.js. За замовчуванням ви вручну передаєте промпти до ChatGPT і вставляєте відповіді у гру. Бази даних, файлів стану та постійного диска немає.

## Гра через копіювання промптів

Встановіть `AI_MODE=manual` (режим за замовчуванням). API-ключ та оплата OpenAI API не потрібні; користуйтеся своїм звичайним чатом ChatGPT у межах його лімітів.

1. Розставте кораблі та почніть гру.
2. Коли хід перейде до AI, з'явиться панель «Передайте хід ChatGPT».
3. Натисніть «Скопіювати промпт» і вставте текст у чат ChatGPT. Якщо браузер не дозволяє копіювання, виділіть і скопіюйте текст вручну.
4. Скопіюйте весь JSON із відповіді ChatGPT та вставте в поле «Відповідь ChatGPT».
5. Натисніть «Виконати постріл ChatGPT». Сервер перевірить координати та визначить результат.
6. Після промаху ходите ви. Після влучання або потоплення AI має ще один постріл: скопіюйте новий промпт і повторіть процедуру.

Відповідь має містити `requestId`, `row` і `column`, як у промпті. Нумерація координат — від 0 до 9. Приймається звичайний JSON або JSON у блоці з потрійними зворотними лапками. Інша партія, застарілий requestId, повторна або недоступна клітинка відхиляються без зміни поля. Повний промпт генерується для кожного пострілу, тому його можна вставляти в той самий або новий чат. Прихованих кораблів людини у промпті немає.

## Запуск локально

Потрібен Node.js 22 або новіший (рекомендовано 24).

```powershell
npm.cmd install
Copy-Item .env.example .env
# У .env вже задано AI_MODE=manual. Для цього режиму ключ не потрібен.
npm.cmd run dev
```

Відкрийте адресу, яку виведе Vite (зазвичай http://localhost:5173).
Інші режими: `AI_MODE=demo` — локальний алгоритм; `AI_MODE=openai` — автоматичні запити до OpenAI Responses API, для яких потрібно заповнити `OPENAI_API_KEY`. Не передавайте ключ у чат і не комітьте його. Режим OpenAI ніколи автоматично не замінюється демо.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd start
```

Зібрана гра доступна на http://localhost:3000. На Linux/macOS використовуйте `npm` замість `npm.cmd`.

## Render

1. Завантажте код у свій GitHub-репозиторій разом із `package-lock.json`, без `.env` і `node_modules`.
2. Створіть Render Web Service з цього репозиторію або Blueprint із `render.yaml`.
3. Build command: `npm ci --include=dev && npm run build`. Start command: `npm start`. Health check: `/api/health`.
4. Додайте `AI_MODE=manual` та `NODE_ENV=production`. У вже створеному сервісі змініть `AI_MODE` з `openai` на `manual` у Environment та натисніть Save and deploy. Для ручного режиму `OPENAI_API_KEY` і `OPENAI_MODEL` не потрібні; їх наявні значення не використовуються.
5. Встановіть `APP_ORIGIN` у точну адресу сервісу, наприклад `https://sea-battle-ai.onrender.com`. Для власного домену використовуйте його адресу. Без кінцевого `/`.
6. Залиште один екземпляр сервера. Диск підключати не потрібно. Blueprint обирає платний план `0.5c-512mb`; тариф можна змінити у Render. На Free засинання сервера призводить до втрати партій.

У ручному режимі користувач сам відкриває ChatGPT. Для автоматичного режиму API-ключ доступний лише серверу, а браузер користувача не потребує акаунта OpenAI.

Збірка потребує `devDependencies` (TypeScript, Vite та типів), навіть коли `NODE_ENV=production`. Файл `.npmrc` також вмикає їх встановлення, щоб раніше створені сервіси з командою `npm ci && npm run build` продовжували працювати. Якщо виникає `TS2688` для `node` або `vite/client`, перевірте Build Command у Render → Settings → Build & Deploy і повторіть розгортання останнього коміту.

## Правила та інтерфейс

Поле 10×10. Флот 4,3,3,2,2,2,1,1,1,1. Кораблі не торкаються навіть кутами. Людина ходить першою; влучання та потоплення дають повторний хід. Вода навколо потоплених кораблів автоматично позначається. При завершенні гри показується флот суперника.

Перед початком можна випадково розставити флот або очистити поле й розмістити кораблі вручну в заданому порядку. Кнопка напрямку змінює орієнтацію. Клік по вже розміщеному кораблю очищає весь флот.

## Ізоляція та пам'ять

- Криптографічно випадковий токен у HttpOnly/SameSite=Strict cookie. У production cookie також Secure та має префікс `__Host-`.
- `Map<sessionToken, Session>` містить одну поточну партію для кожної сесії. Сервер шукає партію тільки всередині сесії її власника; чужий `gameId` не дає доступу.
- Блокування ходу діє на конкретну партію. Версія стану відхиляє повторні та застарілі постріли. У різних вкладках одного браузера спільна сесія; різні браузери/профілі мають незалежні сесії.
- Запити до AI не містять cookie, ідентифікаторів сесій, прихованого флоту людини чи даних інших партій. `store: false`; попередні conversation/response ID не використовуються. Це не обіцянка нульового збереження з боку API-провайдера.
- Кожний постріл AI — окремий промпт. Передаються правила, його постріли, потоплені кораблі, залишок флоту і дозволені координати. У ручному режимі користувач копіює промпт і відповідь; в автоматичному режимі сервер звертається до API. Сервер перевіряє відповідь і сам визначає результат.
- До 8 одночасних API-запитів за замовчуванням. При перевантаженні чи помилці API гравець може повторити хід, а вже зроблені постріли зберігаються. Таймаут одного API-запиту — 25 секунд.
- До 1000 сесій; неактивні сесії видаляються через 60 хвилин. Сервер прибирає їх щохвилини; активний хід не видаляється. Перезапуск, оновлення або засинання процесу знищують усі партії.
- Клієнт отримує повний власний флот і тільки відкриту інформацію про суперника. Опитування стану дозволяє відновитися після оновлення сторінки та тимчасового розриву мережі.

Ліміти налаштовуються через `MAX_SESSIONS`, `MAX_AI_CONCURRENCY`, `SESSION_TTL_MINUTES`. Обмеження HTTP-запитів за IP та частоти створення партій зменшують випадкове навантаження. Для публічного запуску з великим трафіком потрібні додаткові захист від зловживань та контроль витрат у проєкті OpenAI. Максимальну кількість гравців треба визначати навантажувальним тестом.

## Перевірки

Якщо хід AI не виконується, відкрийте Render → Logs і знайдіть `ai_turn_failed`. Журнал містить лише категорію, HTTP-статус, відомий код помилки та request ID; API-ключ і повний текст відповіді провайдера не записуються. `authentication` означає проблему ключа; `quota` — коштів чи лімітів витрат; `model` — доступу до моделі; `rate_limit` — тимчасове обмеження запитів. Гра також показує відповідне повідомлення. При проблемах оплати повтор ходу не допоможе, доки не відновлено доступ до API.

`npm test` перевіряє правила, розміщення, приховування флоту, розділення сесій, відмову чужому користувачу, повторні ходи та поведінку при збоях AI. Тести не звертаються до OpenAI.
